# Fetch Research Lab

This order rebuilds Fetch around Labs, living standardized research records, Lab Libraries, continuous taxonomy indexing, Contractor extraction, and Calendar-owned seasonal presentation. The product contracts live in `Fetch.md`, `Contractors.md`, and `Calendar.md`; this file owns only the cross-system execution order.

## Current implementation seam

Migrations 320 and 321 establish the Labs schema and retire the former Fetch profile/research owner. Deterministic tests exercise account-scoped numbering and lifecycle, the standardized record and sealed taxonomy, Incognito publication, Ask-first and autonomy gates, research orchestration, full-page Library and Index views, and the day/night and initial Halloween surface. The remaining cross-owner work is the serving Contractor connection, Calendar handoff, production-shaped Postgres proof, and real-browser acceptance.

## Remaining work

1. **Connect controlled Contractor research without weakening review.** Build the research-terms input and serving provider behind the existing account-and-book-scoped interface. Refresh ordinary-Lab matches as taxonomy changes, expose Lab numbers only as a dynamic candidate feed, and stage bounded extractions with stable origin identity and self-contained evidence for keep/correct review. Prove Incognito exclusion, idempotent extraction, deletion reference suppression, and no cascade into reviewed knowledge or accepted Memory through the real route and store.
2. **Hand seasonal ownership to Calendar.** Replace Fetch's built-in month check with Calendar's shared account-timezone cultural schedule without creating personal events or changing Fetch's presentation contract.
3. **Prove the data layer against Postgres.** Apply the rebuilt migrations to a disposable production-shaped database and exercise concurrent numbering, ownership, encryption, lifecycle idempotency, deletion residue, blind taxonomy lookup and correction, single-use grants, and cascade/reference boundaries against the real database.
4. **Finish rendered acceptance.** In a real browser at desktop and phone widths, verify day, night, active, archived, dead-record, live-search permission, Incognito, Library, Index, and Halloween states. Browser screenshots prove the surface; they do not substitute for the Postgres run.

Delete this build order when every step has been built and its strongest available verification is recorded in tests, Acceptance where live proof remains owed, or Git for completed runs.
