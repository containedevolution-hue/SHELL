# SHELL

Establishes SHELL as an independent local-first operating environment owning the adaptive Status Bar, FETCH, Research Labs, local data, optional cloud sync, devices, windows, settings, automation, and integrations. Tenari is optional.

**Built:**
- Extracted into its own public repository, preserving `localhub/` history: the canvas, sidecar/local agent, Tauri wrapper, dedup engine, Flow prompts, Pi work, tests, licence, and CI
- A capability discovery contract v1 published at a loopback-only `/v1/capabilities` endpoint
- An MSI-targeted VM profile, read-only host preflight, Linux user-service seam, recovery gates, and a default-off native-desk controller exist; Hyprland has an executable adapter, Windows has a deterministic backend/private driver/authenticated inherited channel — neither platform has completed native runtime acceptance
- Tenari's source-level copy removed from SHELL; recovered Tenari origins/pairing/catalog assumptions still exist as legacy seams pending isolation

**Not built yet:**
- The 13-step build order: finish the capability interface → replace the recovered remote launcher with local app discovery → build the authoritative SQLite data layer → build SHELL Cloud independently → build FETCH Browser → build the window/session model (including Chat's one reserved native slot) → host CE Apps local-first → attach Tenari as an optional integration → stand up SEED → integrate Brics → build the MSI development image → finish SHELL's Core → verify every release layer honestly (tests, builds, real hardware, cloud, Tenari, Brics, and recovery as separate signals)
- Fully separating hard-coded Tenari origins, `/api/hub/*`, account pairing, and the live Tenari catalog into an optional adapter
