# SHELL's Core

Builds SHELL's Core from the revised desktop direction: an intact blinking seed opens the computer's Core. Desktop and Status Bar menus come first; deeper Core navigation follows. Product behavior lives in `../shells-core.md`; this order owns the unfinished sequence.

**Built:**
- A current seam exists: a live app launcher, a separate design study for the revised desktop/navigation, and capability discovery/jailed filesystem access/default-deny browser reach (each independent of the visual study)
- Tenari already exposes bounded Memory MCP reads and evidence proposals (not yet unified with Core/Memory Box/SEED)
- SEED has a local append-only corpus and ingest importer (backup, restore, curation, and the sealed Memory Box mount are not built)
- System Dashboard defines gauge behavior (no free-placed gauge layer over Core yet)

**Not built yet:**
- The 13-step build order: establish desktop navigation and typed node types → publish the index contract → build the Core opening surface → build accessible Files/category navigation → separate system and aftermarket globes → mount apps and projects → unify connection status into the Trunk → build Memory Box → mount SEED inside Memory Box → build the gauge layer → build SEED backup lanes → build restore/disaster recovery → bound Memory Grove export
- Evidence gates: a rebuild-produces-same-nodes proof, distinguishable move/link/mount/delete receipts, system-path write resistance, per-assistant grant isolation, prompt-injection resistance, honest Trunk conduit state, leak-free gauges, independent backup-lane restore, and provenance-preserving Memory Grove export
